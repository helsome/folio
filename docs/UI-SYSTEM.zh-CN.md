# Folio UI 系统

Folio 是一个安静（quiet）的金融工作区：密度足以支撑实时行情工作，又足够平静，让用户的注意力始终停留在决策上。本文是渲染进程中新增 UI 工作的一份简明契约。

## 基础

- 使用 `apps/electron/src/renderer/styles/index.css` 中的令牌层。
- 优先使用不透明表面（`bg-background`、`bg-surface`、`bg-surface-muted`），而不是模糊、渐变和半透明玻璃效果。
- 控件使用 8–10px 圆角，面板使用 10–12px 圆角，并使用 1px 的 `border-border`。
- 使用 `text-foreground`、`text-foreground/52` 和 `text-foreground/38` 分别表示主文字、次级文字和弱化文字。不要自创页面专属的灰色。
- 仅用于表达数据含义或状态——而非装饰——才使用 `text-positive`、`text-negative`、`text-warning` 和 `text-info`。
- 数值使用 `tnum`/表格数字（tabular numerals）。价格和百分比在数据缺失时必须退化为破折号（em dash），而不是显示 `NaN`、`undefined` 或空标签。

兼容性的 `mac-*` 类仍保留给现有界面使用，但会映射到相同的低调令牌表面。新组件应直接使用语义令牌。

## 组件规则

在新增一次性控件之前，先使用共享的基础组件：

- `Button`、`Input`、`Dialog` 用于操作和表单。
- 基于 Radix 的 `Tabs`、`Select`、`DropdownMenu`、`Tooltip` 和 `Switch`，以获得键盘行为和无障碍角色。
- `EmptyState`、`ErrorState`、`StatusDot` 和 `Skeleton` 用于如实呈现状态。
- Lucide 图标在控件中使用 14–18px；纯图标控件需要无障碍标签，当含义不明显时还需要 tooltip。
- Sonner 是全局的临时反馈通道。重要错误也应保留在失败操作附近的行内位置。

不要仅仅为了给标题分组而添加卡片。优先使用区块分隔线或紧凑的表格行。卡片仅保留给有意义的对象、决策界面或高信息量摘要。

## 工作台外壳

外壳（shell）有三个稳定区域：

1. 一个 64px 的全局图标栏，包含今日、发现、工作区、投资组合、对比、提醒和设置。
2. 一个上下文相关的次级面板，用于会话、自选清单、研究导航或设置导航。
3. 金融工作区，外加一个可选、可调整大小的 Agent 面板，面板尺寸以 Allotment 为权威来源。

当前证券存储在 `activeSymbolAtom` 中；视图、SecurityHeader、图表和 Agent 上下文必须读取它，而不是维护各自的本地副本。工作区上下文通过现有的 `WorkspaceContext` 原子（atom）暴露，应包含在 Agent 请求中，并以上下文徽标的形式可见。

## 页面模式

### 今日

使用一个主视觉/搜索界面、三个高信息量快捷操作，然后是安静的区块，用于每日简报、市场脉搏，以及投资组合/自选清单的关注内容。每个区块都应如实呈现加载、空或错误状态，不要假装不可用的数据是零。

### 发现

任务族使用紧凑、易于扫读的行。结果采用类似表格的表头，每个候选标的一行，包含评分、关键指标，以及用于研究、对比和自选清单的图标操作。

### 证券工作区

将 SecurityHeader 保持在概览/图表/财务报表/新闻标签栏的上方。图表持有当前标的与周期控件；数据新鲜度应显示在数据源旁边，而不是孤立的全局横幅中。

### Agent 面板

将模型与思考级别控件保持在顶部。显示工作区上下文徽标、紧凑的轮次历史，以及以可折叠进度行呈现的工具活动。结构化的行情、投资组合和研究输出应作为决策对象来阅读，而不是聊天气泡。一次运行在活动期间必须暴露停止操作，在第一条消息之前提供有用的空状态。

### 设置

使用两级结构：左侧面板为上下文导航，内容区域为 Radix 标签页。常规设置（General）包含浅色/深色/跟随系统的主题选择器。提供商/API 凭据属于连接（Connections）或模型（Models）设置，保存后绝不以明文渲染。

## 状态契约

每个数据驱动的界面都遵循以下顺序：

- 加载中：使用小型骨架屏或一行低调的 `Loading…` 文字。
- 成功：在相关处渲染带来源与新鲜度的数据。
- 空：说明缺少什么，以及什么操作可以填充它。
- 错误：解释用户可安全理解的失败原因，并提供重试或配置入口。
- 部分：展示可用数据，并标明不可用的能力类别。

绝不虚构时间戳、行情、估值、投资组合总值或 Agent 回答。不要将原始提供商错误带入渲染进程文案。

## 视觉 QA

视觉测试台在指定尺寸下捕获黄金状态：

```sh
cd apps/electron
node e2e/visual.mjs
```

在 `apps/electron/e2e/artifacts/ui/` 中检查输出。必需的冒烟检查如下：

```sh
bun test
bun run typecheck
bun run build
FINAGENT_AGENT_PROVIDER=local bun run test:e2e
```

在发布新页面之前，在 1440×900、1280×800 以及更大的视口下检查：溢出、被裁切的焦点环、难以阅读的弱化文字，以及侧栏/次级面板是否会在金融工作区变得不可用之前折叠。
