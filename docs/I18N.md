# Folio I18N — 中文 / English 双语架构 (V8)

## Supported Locales (v1)
- `zh-CN` 简体中文
- `en-US` English

第一版只正式支持这两个(§1)。`System` 偏好按 OS locale 解析:zh-* → `zh-CN`,其他 → `en-US`(§17–18)。
不支持的语言一律 fallback 英文。

## Locale 契约(单一来源)
类型定义在 **@finagent/core**(`packages/core/src/locale.ts`),所有包共享:
- `SupportedLocale = 'zh-CN' | 'en-US'`
- `LocalePreference = 'system' | SupportedLocale`
- `AppPreferencesSnapshot = { preference, systemLocale, effectiveLocale }`
- `LocalePreferenceStorage = { locale?: LocalePreference }`

解析逻辑在 **@finagent/i18n**(`packages/i18n/src/locales.ts`):`resolveLocale(preference, systemLocale)`、
`isSupportedLocale/isLocalePreference` 类型守卫、`LOCALE_LABELS`(语言选择器用 endonym)。

## 包结构
```
packages/i18n/
  src/
    locales.ts     # locale 解析 + 守卫 + endonym labels
    format.ts      # Intl formatters（自动跟随当前 locale）
    i18n.ts        # createI18n / createSyncI18n（renderer/main/test 共用）
    resources.ts   # 资源注册 + key parity checker（i18n:check 用量）
    error-messages.ts  # ApiError.code → errors.* 翻译解析
    locales/{en-US,zh-CN}/<namespace>.ts   # 每个 namespace 一个文件
    locales/{en-US,zh-CN}/index.ts         # 资源 bundle 聚合
    locales/keys.ts # NamespaceResource / SameKeysAs<enX> 类型守卫
```

## 依赖
- `i18next`(翻译引擎,离线资源,无 CDN/SaaS)
- `react-i18next`(renderer 只用这一层)
依赖只加这两个;不引入 detector/CMS/远程翻译。

## Namespace 策略(§8)
按 domain 分文件:`common navigation today discover security research thesis portfolio compare
alerts automation agent skills performance settings connections onboarding evaluation diagnostics errors`。
`common` 只放跨页面复用词(Save/Cancel/Delete…)。禁止把所有东西塞进一个 4000 行 JSON。

## 添加翻译的步骤(给开发者)
1. 找到对应 namespace;没有就新建 `packages/i18n/src/locales/{en-US,zh-CN}/<ns>.ts`。
2. en 文件:`export const portfolio = { totalAssets: 'Total Assets' } satisfies NamespaceResource;`
3. zh 文件:`export const portfolio = { totalAssets: '总资产' } satisfies SameKeysAs<typeof enPortfolio>;`
   —— `SameKeysAs` 保证 zh 至少包含 en 的所有 key(缺翻译 = 编译失败)。
4. 在 `locales/{en-US,zh-CN}/index.ts` 里注册。
5. 组件里 `const { t } = useTranslation(); t('portfolio.totalAssets')`。嵌套组照样 `t('settings.sections.application')`。
6. 数字/日期/货币用 `@finagent/i18n` formatters,不要手写 `$`/`K/M/B`/`YYYY-MM-DD`。

## Formatter 规则(§52–59)
- `formatCurrency(v, 'USD')` → Intl,en `$1,234.56` / zh `US$1,234.56`
- `formatCompactNumber(v)` → en `1.2B` / zh `12亿`(不硬编码 K/M/B)
- **百分比防 100x bug(§56)**:`formatPercent(v)` 的 `v` 是已 ×100 的值(23.5 → `+23.5%`);
  `formatPercentRatio(r)` 的 `r` 是 0..1。别把二者混用。
- `formatDate/formatDateTime/formatMarketTime/formatRelativeTime` 跟随 locale。
- Locale 只控制**展示**;金融计算 / 市场时区语义不变(§59)。

## 持久化(§14–16、§89)
主进程拥有 `app-preferences.json`(`apps/electron/src/main/app-preferences.ts`,
JsonFileStore)存储 `{ locale }`。默认 `system`。切换语言:`appPreferences:update` IPC →
写 userData → 返回 snapshot → renderer `changeLanguage`,跨启动保留。

## 即时切换(§19–20)
`I18nProvider`(packages/ui/src/i18n/I18nProvider.tsx)在 FinagentClientProvider 内:
- 启动读主进程 snapshot 初始化 i18next
- `changeLanguage` → react-i18next 全树重渲染(无重启)
- `document.documentElement.lang` 同步更新
组件里用 `useTranslation()`/`useI18n()`。

## Agent 语言行为(§41–46)
- **单一 system prompt,不 fork**(§43):运行时只在 prompt 里加一段稳定语言指示
  (foundation 已在 `packages/shared/src/agent/pi-runtime-adapter.ts buildPrompt` 落地)。
- 新 Agent 回复默认跟随 effective locale(`AgentRunInput.locale` → run-manager → pi adapter)。
- 用户显式要求另一种语言(如「Answer this in English.」)优先。
- 新 Research 报告记录生成语言:`ResearchReport.locale`;历史报告保持生成时原文,不机器翻译。
- Research diff 只 diff 结构化字段;解释文本跟随当前 run locale,不翻译 previous report。
- 禁止翻译:ticker、工具名、能力/技能/策略 ID、数据字段、引用(§11)。

## Evaluation locale 规则(§37–38、§73–75)
- `EvaluationCase.locale`(可选,默认 `en-US`)保证旧 benchmark 可复现。
- `eval:smoke / eval:full` 的基准输出由 case/experiment 的 locale 决定,**不受**开发者 UI 语言影响。
- 中文子集:`folio-agent-v1-zh`(10–20 条高价值用例,fixture 可跑),新增 `eval:i18n-smoke`。
- 语言环境不会导致额外 trace 数据泄露;trace metadata 允许记录 `locale`(不进敏感性数据)。

## 验证命令(§81–84、g 137)
```bash
bun run i18n:check      # en/zh key parity + 插值 parity(CI 门禁)
bun run eval:smoke -- --mode fixture --baseline folio-agent-v1   # 英文基准不变
bun run eval:i18n-smoke # 中文子集 smoke(如有)
bun test --isolate      # 全量单测
bun run typecheck       # 全包 typecheck
bun run build           # 打包构建
```
`i18n:check` 已接入 `.github/workflows/eval-smoke.yml`(PR 必过)。

## 代码语言纪律(§104–106)
源码标识符/类型/接口/event/domain ID 一律英文。翻译资源只负责 DISPLAY。
IPC payload、JSON schema、数据库、provider 请求、evaluation dataset schema 保持稳定英文 key。
